Paired against the vLLM runs, with the independent audit (2026-10-27; AUDIT-2026-10-27.md)

  1. vLLM run-to-run variation: cause. It is not batching or speculation: every vLLM capture ran alone. Rows inside the first 2,045-token prefill chunk are bit-identical between the two vLLM runs; rows beyond it almost never are (verified: e00 512/512 and d01 419/419 identical inside; a08 and b00 0/512 beyond). Multi-chunk prefill is not run-to-run deterministic on this stack (consistent with the earlier indexer top-k ordering finding).
  2. The headline pairs CuteAFD against the mean of both vLLM runs, since one vLLM run is one draw of a varying engine. P-B generated rows at 8-16K: KL +0.0050 [+0.0031, +0.0071], top-1 −0.87 pts (against V1 alone +0.0044 / −1.04; against V1r +0.0057 / −0.70). The 2-8K top-1 difference (+0.39 against V1) does not hold against V1r.
  3. Length and content. The 8-16K bucket is block B (long code reading: all 12 windows, 82% of the bucket's rows). Within block A, the only block present at every length, the KL difference is flat (+0.0029 / +0.0017 / +0.0028). The difference is concentrated in long code reading; whether length or content drives it is not separated here. NLL is also higher for CuteAFD below 8K (+0.0069, +0.0073).
  4. Against the panel's own paired bar (0.005): CuteAFD's top-1 loss upper bound is 0.0080 (vs V1) / 0.0067 (vs V1r), so it is not shown within that bar on top-1 (the bar is defined for same-engine changes; applied here by analogy only).
  5. Mechanism candidates. Besides FP8 projections / head / KDA, the engines differ in the DSA indexer key format (CuteAFD BF16 keys, vLLM FP8), attention placement, KDA output sharding, prefill chunk geometry, BF16 logits in vLLM, and W8A8 prefill (specific to prefill-shaped scoring). Follow-up F1 tests the switchable ones; its KDA arm also drops KDA output sharding (launcher coupling), so it is not a clean single-factor test. CuteAFD's predictive entropy is higher in 18 of 18 8-16K windows (0.580 vs 0.523; teacher ~0.53), which is why its NLL difference is larger than its KL difference on this greedy-generated text.
  6. Q2 wording. Six documents; the per-type intervals rest on 3 clusters each. With t-intervals, prose [−0.0013, +0.0050], code [−0.0135, +0.0077]; one code window (c2-064k) drives the code figure. Stated as: no NLL difference larger than about ±0.005 nat at 32K-128K at this sample size. Engine-vs-engine disagreement is about 1.8x vLLM's own run-to-run disagreement on matched documents.
  7. Trailing context rows. All 30 such spans are the same unrelated filler file; engine-vs-engine KL there is 0.7-3.1 nat and vLLM-vs-itself up to 1.96 nat. These rows are highly sensitive to any numerical change; they are not evidence about the reference.
  8. Panel text source (noted): P-B's generated text is greedy output of the official FP8 model in his engine's arithmetic family; any resulting bias would favour CuteAFD, i.e. it runs against the observed difference.
