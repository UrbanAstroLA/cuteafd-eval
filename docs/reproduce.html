0. What you need

  • Two GPUs of the RTX PRO 6000 Blackwell class (about 96 GB each), Docker with the NVIDIA container toolkit.
  • About 300 GB for the checkpoints and images, and several hundred GB of scratch for the Block Q captures (full-vocabulary rows: about 160 GB per engine for P-A, P-B and Q2 with repeats).
  • Python 3.10+ (drivers and checkers: standard library), and an environment with numpy and scipy for the scorers.
  • Nothing else on the GPUs. nvidia-smi --query-compute-apps does not list every graphics client; check the full nvidia-smi output.

3. Serve vLLM (arm V1)

5. Block Q: precision

Order: C1 twice, C0 once, then V1 twice. Exact commands are in the instrument READMEs:

  • CuteAFD, P-B: tpurtell's own fidelity CLI, full tier, prefill score path, dataset revision a7e7d1b4; then the validation of our port against it (stage0/scorers/README.md, section 6, "P-B validation plan"). P-A and Q2: the engine's glmf-teacher-kl.py path through the bench endpoint, with the plans from plans.py (section 2).
  • vLLM, all panels: restart the v0.9.2 server in capture mode with stage0/capture-vllm/start-v092-capture.sh, run capture.py capture per panel and pass, capture.py verify, then restore the normal server (stage0/capture-vllm/README.md, "Commands for the GPU stage").
  • Scoring: stage0/scorers/README.md, section 9, "Commands after capture" (score_pa.py, score_pb.py, score_q2.py). Run stage0/scorers/selfcheck.sh first.

The published summaries are in ../results/2026-10-26-cuteafd-vs-vllm/q/.

5a. Panel P-A from the teacher dataset

P-A's reference is brandonmusic's BF16 teacher: full-vocabulary FP32 logits of zai-org/GLM-5.3-Flash-BF16 @ a6c167b62691b2bac901344b65cb651a70f53e43 for 25 qualification windows, final-0000 to final-0024 (2,048 tokens each, 2,047 prediction positions, vocabulary 154,880). Its public home is brandonmusic/GLM-5.3-Flash-ShapleyMCG-K4-Evidence at revision 32afb8875f830528d5545c20a51846b56c537f44 (no licence stated). This comparison first scored the same files from brandonmusic/GLM-5.3-Flash-BF16-Teacher-Logits @ 95f4fdd9, which is no longer public; every teacher file, token array and the mask are byte-identical. Identity, windows and hashes: ../results/2026-10-26-cuteafd-vs-vllm/q/pa/PROVENANCE.json.

  1. Download only what P-A reads (about 31.7 GB):
huggingface-cli download brandonmusic/GLM-5.3-Flash-ShapleyMCG-K4-Evidence --repo-type dataset \
  --revision 32afb8875f830528d5545c20a51846b56c537f44 --local-dir <datasets>/glm53-k4-evidence \
  --include "README.md" "SHA256SUMS" "teacher/logits/window-00*.safetensors" \
    "calibration/windows/arrays/final-*.tokens.npy" "calibration/windows/arrays/causal-mask-2048.npy"
  1. Lay it out and check it. The tools read the layout of the dataset originally scored (logits/, calibration/panel-v1/arrays/, dataset-manifest.json). This links the downloaded files into that layout, writes the small manifest plans.py reads from PROVENANCE.json, and checks every hash:
python3 - <<'EOF'
import hashlib, json, os
E, T = "<datasets>/glm53-k4-evidence", "<datasets>/glm53-flash-teacher-logits"
P = json.load(open("results/2026-10-26-cuteafd-vs-vllm/q/pa/PROVENANCE.json"))
os.makedirs(f"{T}/logits", exist_ok=True); os.makedirs(f"{T}/calibration/panel-v1/arrays", exist_ok=True)
def link(src, dst):
    if not os.path.lexists(f"{T}/{dst}"): os.symlink(os.path.abspath(f"{E}/{src}"), f"{T}/{dst}")
for w in P["windows"]:
    n = w["window_id"].split("-")[1]
    link(f"teacher/logits/window-{n}.safetensors", w["teacher_file"])
    link(f"calibration/windows/arrays/{w['window_id']}.tokens.npy", w["tokens_file"])
link("calibration/windows/arrays/causal-mask-2048.npy", "calibration/panel-v1/arrays/causal-mask-2048.npy")
json.dump({"model_revision": P["dataset"]["source_model_revision"], "logit_files": [
    {"window_id": w["window_id"], "path": w["teacher_file"], "token_ids_sha256": w["tokens_npy_sha256"],
     "document_id": w["document_id"], "domain": w["domain"]} for w in P["windows"]]},
    open(f"{T}/dataset-manifest.json", "w"), indent=1)
def h(rel):
    d = hashlib.sha256()
    with open(f"{T}/{rel}", "rb") as f:
        for b in iter(lambda: f.read(1 << 24), b""): d.update(b)
    return d.hexdigest()
bad = [w["window_id"] for w in P["windows"] if h(w["teacher_file"]) != w["teacher_sha256"]
       or h(w["tokens_file"]) != w["tokens_npy_sha256"]]
bad += ["mask"] if h("calibration/panel-v1/arrays/causal-mask-2048.npy") != P["dataset"]["causal-mask-2048.npy sha256"] else []
print("mismatches:", bad or "none")
EOF

Each teacher file is one F32 tensor logits, [2047, 154880]; each token array is int32, 2,048 ids; the mask is a 1-D all-ones validity mask (every position is scored).

  1. Plans. cd stage0/scorers && python3 -B plans.py --out plans --panels pa --teacher <datasets>/glm53-flash-teacher-logits writes the CuteAFD plan and the vLLM registry for rows 0-2046 of every window; their sha256 must equal those in stage0/scorers/plans/pa.meta.json (and the scorers README, section 2). The meta file's dataset_manifest_sha256 will differ: it hashes the original dataset's manifest, which item 2 of this step replaces with a minimal one. The vLLM registry also differs from the recorded sha256 in one field only: its schema label was renamed for publication (engine-compare.vllm-registry/1); with schema removed, its content equals the original (checked 2026-10-28). The CuteAFD plan's sha256 matches exactly.
  2. Capture each arm twice (step 5): CuteAFD through its bench endpoint, with the scoring config and an API key in CUTEAFD_API_KEY,
python3 <cuteafd>/scripts/bench/glmf-teacher-kl.py --url http://127.0.0.1:8001 --plan stage0/scorers/plans/pa.cuteafd-plan.json \
  --dump-root <the server's PROBE_DUMP_ROOT> --path prefill --out <run>/q/rows/pa-C1-rep1

and vLLM with capture.py capture for panel pa (stage0/capture-vllm/README.md).

  1. Score (CPU, numpy and scipy):
cd stage0/scorers
<venv>/bin/python -B score_pa.py score --arm C1=<run>/q/rows/pa-C1-rep1 --arm C1r=<run>/q/rows/pa-C1-rep2 \
  --arm V1=<V1 rows> --arm V1r=<V1 repeat rows> --pair C1,C1r --pair V1,V1r --pair V1,C1 --out <out> --jobs 8

(follow-up F3 adds --arm V2=<second launch rows>). Definition, per row r of each window (row r predicts token r+1, with r + 1 tokens of history): KL(teacher ‖ engine) = Σ over all 154,880 ids of p_t (log p_t − log p_e), both from a float64 log-softmax of the stored rows; NLL of the actual next token; top-1 with ties to the lower id; confident top-1 over rows whose teacher top probability is at least 0.5. Means are position-weighted; 95% intervals resample the 25 windows (20,000 replicates, seed 20260929).

  1. Compare <out>/pa-<arm>.json with ../results/2026-10-26-cuteafd-vs-vllm/q/pa/ (and q/pa-v2/ for V2): overall and per-window KL, NLL, top-1. The scorer reproduces itself exactly on the same rows (the scorers README, section 8: the teacher scored as its own engine gives KL 0 at every row). For the tails and positions, take the per-row kl of <out>/pa-<arm>.rows.npz (type-7 quantiles, numpy's default) or write the CSV layout of ../results/2026-10-26-cuteafd-vs-vllm/q/rows/README.md and run python3 tools/kl_tails.py --pa <that file>; compare with q/tails/pa-tails.json, which records the sha256 of the file it was computed from.

The P-A per-position file is ../results/2026-10-26-cuteafd-vs-vllm/q/rows/pa-rows.csv; python3 tools/kl_tails.py --check recomputes the published tails from it.

On each served engine in turn (vLLM first in this run), with nothing else on the GPUs:

python3 stage0/drivers/block_t.py --base-url http://127.0.0.1:8001 --label V1-r1 --out <run>/t/V1-r1-block-t.json
python3 stage0/drivers/block_t.py --base-url http://127.0.0.1:8001 --label C1-r1 --out <run>/t/C1-r1-block-t.json

The driver refuses to start if any prompt differs from stage0/prompts/T/index.json, inserts a per-request nonce so no prompt is served from cache, records every request's seed, and writes no text. --dry-run prints the plan.

7. Block L: long output

One stage per invocation, checking the engine's logs and memory between stages:

python3 stage0/drivers/block_l.py --base-url http://127.0.0.1:8001 --label V1-r1 --out <run>/l/V1-r1-L1.json --stages L1
#   then --stages L2, L3 and L3s, each with its own --out
python3 stage0/drivers/analyze_l.py <run>/l/V1-r1-L1.json <run>/l/V1-r1-L2.json <run>/l/V1-r1-L3.json <run>/l/V1-r1-L3s.json --out <run>/l/V1-analysis.json

analyze_l.py re-tokenizes in a CPU-only container and runs each code reply's hidden tests in a --network none sandbox (stage0/drivers/README.md).
