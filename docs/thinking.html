Thinking length: what changes how long the model thinks

On code, CuteAFD's FP8 KDA setting accounts for most of a length gap between its two arms (supported): switched off, the BF16-core arm thinks about as long as the native 6-bit core. On the vLLM fork the core's stored precision changed nothing detectable. On science questions, the core's precision was not detected to change the stop decision on either engine (established), but how long the model thinks in free generation there is not known (open: one question, one engine). Whether shorter thinking costs correctness is open.

The science-question runs use a public multiple-choice benchmark; its name appears only in those runs' files. Thinking length is measured as reasoning tokens or characters per reply, with distinct seeds per repeat.

Code: the FP8 KDA setting

Why does CuteAFD's BF16-core arm think shorter on code than its native 6-bit-core arm?

supported Most of the gap goes with CuteAFD's FP8 KDA setting. The native 6-bit core thought 1.26 [1.24, 1.29] times as long as the BF16 core run through the engine's FP8 defaults, on 12 new code prompts. Switching the KDA setting off lengthened the BF16-core arm 1.31 [1.24, 1.38] times; turning the head and prefill FP8 off after that added nothing detectable. On the vLLM fork, which runs neither core through these FP8 paths, the two cores thought equally long: 1.00 [0.96, 1.04]. The setting changes both the KDA projection format and, on two GPUs, KDA output sharding, and the run does not separate the two.

Why this strength: Frozen protocols, one prompt family (16 code prompts, 12 primary) and one checkpoint pair; the engine contrast and the setting ablation point the same way. Scope: GLM-5.3-Flash on two RTX PRO 6000 Blackwell Max-Q (300 W); CuteAFD v4.0.0 and vLLM fork v0.9.2 with the local core loader; K4-Core-K6 and its BF16-core derivative; code prompts, thinking on.

Science questions: the stop decision

Does the core's precision change when the model decides to stop thinking on science questions?

established Not detected on either engine. On the vLLM fork, whole BF16 core − 6-bit core in log p of ending the thinking at the trace's close: +0.005 [−0.009, +0.019] on 11 questions and −0.0109 [−0.0315, +0.0046] on 30 new ones. On CuteAFD: −0.0144 [−0.0497, +0.0187] on the 30 new questions and −0.0028 [−0.0263, +0.0195] over all 41. A secondary measure, the stopping hazard, shows small resolved shifts on both engines.

Why this strength: Frozen protocols on two engines, not detected on either (the 11-question set: the vLLM fork in the thinking-length run, CuteAFD in the core-swap run). The 30 new questions agree; that run is labelled exploratory in its own record, with its reading rule frozen before its first launch. The bound is the widest interval end, −0.0497. Scope: GLM-5.3-Flash on two RTX PRO 6000 Blackwell Max-Q (300 W); teacher-forced traces of science questions; vLLM fork v0.9.2 with the local core loader, CuteAFD v4.0.0; K4-Core-K6 and its BF16-core derivative.

Science questions: free-generation length

Does the core's precision change how long the model thinks in free generation on science questions?

open Not known. It was measured on one question, on the vLLM fork only: BF16 core / 6-bit core 0.80 [0.51, 1.14] in geometric-mean completion tokens, wider than the frozen band, so the frozen reading is inconclusive. On finished replies only, post hoc, 0.97 [0.78, 1.21].

Why this strength: One question, one engine, and the frozen reading is inconclusive. Scope: GLM-5.3-Flash on two RTX PRO 6000 Blackwell Max-Q (300 W); vLLM fork v0.9.2 with the local core loader; one science question.

Does shorter thinking cost correctness?

Does shorter thinking cost correctness on code?

open Not settled. The 1.26x length gap between CuteAFD's two arms came with no detected difference in all-tests-pass: +1.6 points [−7.8, +10.9]. But in a post hoc look the arm with every FP8 path off passed more often than either CuteAFD arm (+17.5 points [+7.8, +28.6] against the BF16-core default), which also holds after a correction for 13 looks; that arm ran a day later on the same prompt family.

Why this strength: One pre-set comparison not detected, one post hoc comparison resolved; mixed. Scope: GLM-5.3-Flash on two RTX PRO 6000 Blackwell Max-Q (300 W); CuteAFD v4.0.0 and vLLM fork v0.9.2; 16 code prompts with hidden tests.

Basis (6 findings) and what it does not show
  • context CT-core-code — the length gap
  • supports FA-pass-ck6-ck6x — the length gap without a pass difference
  • contradicts FA-pass-fpre — all FP8 off passed more often (post hoc)
  • context FA-pass-kda — KDA off alone (post hoc)
  • context CT-tests — pass counts
  • context V3-l-tasks-128k — shorter CuteAFD replies, equal code passes (K3.25)

Does not show

  • That shorter thinking is free.
  • That the FP8 paths cost correctness: the result is post hoc, from one run on another day.

A lead that did not repeat

A layout lead on the vLLM fork (two attention projection groups in BF16) was found after looking at 11 questions and tested on 30 new ones, where it was not detected; see leads that did not repeat.
